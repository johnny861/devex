# Shell Audit — Phase 0

Baseline inventory and measurements for the modernization plan
([`../terminal/shell-modernization-plan.md`](../terminal/shell-modernization-plan.md)).

Captured **2026-11-18** on the live host:

| | |
| --- | --- |
| macOS | 26.5.2 (arm64) |
| zsh | 5.9 (system, `/bin/zsh`) |
| Terminal | WezTerm, MesloLGS Nerd Font Mono 14, 0.8 opacity |
| Measured by | 20 warm runs per variant, median reported; subprocess wall clock |

Nothing in this directory is generated from the docs — every number below came from the live
config. That is the point: the previous guide had drifted far enough that it described a shell
that no longer exists.

## Headline findings

0. **Remediated 2026-11-18:** startup is down from ~1.36–1.52 s to **387–441 ms** by replacing jenv
   with a static `JAVA_HOME` and nvm with mise. Remaining cost is pyenv (~294 ms).
0b. **Remediated 2026-11-22:** the leaked `SAKANA_API_KEY` export is gone, `PATH` has zero
   duplicates (25 clean / 49 interactive), and history is timestamped, shared and deduped
   (50 000 entries). Same file: [changes.md](changes.md).
1. **Powerlevel10k is not the startup problem.** It costs 9–35 ms. The version managers cost
   **~1.27 s of the ~1.36 s total** — nvm alone is ~675 ms.
2. `compinit` was never called by the config; it ran because **nvm's bash completion script**
   called it (`~/.nvm/bash_completion:91`). Completion was a hidden dependency of nvm.
3. `jenv` cost ~329 ms and pinned a single Java version (17.0.17) that never changed in use.
4. `.zshenv` mutated `PATH` and was sourced twice per shell, so every shell duplicated four
   Android paths: 33 entries with 8 redundant (pre-fix).
5. All config files parse cleanly; the only startup errors are the p10k `gitstatus` failure and
   a `monitor` option error.
6. One secret was in plaintext: `SAKANA_API_KEY` in `~/.zshenv` (rotated and removed).
7. Repo configs are stale in ways that matter: `.pk10.zsh` is a filename typo that would never
   load, and zoxide (documented) is not installed.

## How to re-run

The scripts that produced `raw/` are in [`../scripts/audit/`](../scripts/audit/). Each takes an
output directory and uses only the standard library plus the tools already installed:

```sh
scripts/audit/run.sh          # regenerate audit/raw/* from the current config
scripts/audit/after.py        # only the before/after timing snapshot -> timing-after.json
```

The markdown analyses are written by hand from those outputs, deliberately: the numbers change,
the reasoning should not silently change with them.
